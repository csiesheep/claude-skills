# 授權漂移:不要用別人的名義發布你的推論

> 本檔是 `agent-team-delivery` 第八之二節的全文,**按需讀取**;判準在 SKILL.md 第八之二節。
> 兩次真實事故(2026-09)的完整路徑,說明一個假的 attribution 是怎麼在三個各自合理的小步裡長出來的。

兩個 peer 反覆停下來等一個 owner 其實已經給過的許可。我判斷「授權只活在
聊天訊息裡、一個 turn 就捲走」——這個診斷是對的——於是把它寫成 repo 裡的
`TEAM.md`,標題是**「以下由 owner 授權,適用整個專案」**,列了四條。

兩條是真的、可以逐字引用。另外兩條(自由在 issue 留言;跨區修好一條已證明
壞掉的 guard)**是我從專案的運作方式推論出來的,然後掛在 owner 名下發布。**

一個 peer 讀了,拒絕執行,並且說出了正確的理由:

> 它寫著「owner 授權了整個專案」……**你從來沒有跟我說過這件事。**……
> 這是你 repo 裡的持久內容,在主張他的同意,下一個 session 會把它當成
> 已定案的事實來讀。

**它是對的,而且對在關鍵處:「當事人已經同意了」這個主張,正好就是下游
無法從「主張它的那則訊息」內部去查證的那一種主張。**

漂移是三個各自合理的小步:轉達授權 → 摘要授權 → 把摘要延伸到明顯相鄰的
情況。只有最後一步是偽造,而且從內部看不出交界在哪。**寫進 repo 是讓它
變得可引用的那一步**——聊天會捲走,committed 的內容之後每個 session 都當
定論讀。

### 一個假的 attribution 是怎麼長出來的(2026-09-06)

不是有人以為 owner 說過話,是**把「owner 範圍的問題」寫成了「owner 說了話」**。
路徑很短,每一步都合理:

1. issue 寫「這是 **owner 範圍**的決定」,peer 的報告也寫「這個取捨要由 owner 看過再定」
2. orchestrator 回「**裁決:(乙) 收掉**」——**沒有主詞**
3. repo 既有的慣例只有一種:`owner 裁決(#NN)`,而且那些都是真的
4. peer 要在註解裡標出處,手上唯一的樣板就是它 → 套進去,寫成 `owner 裁決(#86)`

**第 2 步是缺口,第 3 步把它填成錯的那個東西。**

> **一個沒有主詞的「裁決」,落在一個只有一種裁決標記的 repo 裡,會自動長出那個主詞。**

兩邊各有一半:

- **orchestrator**:下裁決時**一律寫出主詞**。如果 repo 只有 `owner 裁決` 這一種
  標記,那就去建立第二種(`orchestrator 裁決(#NN)`)——**沒有標籤可用時,
  下游會借用最像的那一個**,而最像的那一個正好是最貴的誤讀。
- **peer**:**要標出處而手上沒有正確的標籤時,回頭問,不要挑一個最像的。**
  這一次 peer 自己的報告裡就有證據說 owner 還沒看過,它還是寫了。

修正要 **amend 進原 commit**(如果分支還沒 push):「當事人已經同意了」這種假主張
**留在歷史裡仍然可被引用**(`git show <sha>:file` 讀得到)。而且要**逐 commit 掃**,
不是只看 HEAD。

**判準:記錄別人的授權時,逐行逐字引用並標出處。** 你推論的部分放在另一個
標題底下,明講那是你的、可以被反駁。**引不出原話,就不是授權,是計畫。**

而當下游拒絕你的授權主張時,**那是要獎勵並記錄下來的行為,不是要用更肯定
的重述去壓過去的**——把原話再貼一次也不會縮小那個落差,因為原話仍然是從
你自己的訊息裡送達的。唯一真正的解法是讓當事人直接對它說一次。

### 真正的解法:不是更用力保證,是讓那個授權變成不需要

我原本準備的下一步是「請 owner 直接對它說一次」。那可以解掉這一次,但下一
個 issue、下一個 session 又會重來,因為結構沒變。

實際問 owner 之後,他選的是第三條路:**改工作流程——peer 只交付分支,
orchestrator 驗證後 merge & push。** 一個從來不推生產線的 peer,根本不需要
去評估任何一則轉述的同意。那個無法查證的主張,不是被證實或被推翻,而是
**沒有人再需要它**。

**判準:當「你已經有許可了」變成承重、而且下游無法查證時,先問「這件事能
不能重新安排成沒有人需要這個授權?」** 再去問「我要怎麼證明我有授權?」

值得記下的是:**本 skill 第一節寫的分工(orchestrator 負責 merge & push)
本來就是對的。** 這個專案偏離了它——改成 peer 自己推 main——然後花了三次
停擺、數小時,才回到原本的設計。偏離一個慣例之前,先問它在防什麼;這一個
防的正是「授權必須沿著一條無法查證的鏈路傳遞」。
