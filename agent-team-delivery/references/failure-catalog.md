## 儀器與環境——量到的不是你以為的東西

### [stale-cache] 舊的快取 / 舊的 origin
**症狀**:改了 JS/CSS,瀏覽器裡量到的數字沒變,或變得莫名其妙。
**為什麼騙人**:service worker 快取優先,query string 不一定穿得過(`ignoreSearch`)。而且診斷出一次不等於下次會避開——同一個 session 裡我二十分鐘後在同一個瀏覽器上又踩一次。
**判準**:驗改過的資源用**全新 origin**(換 port),不是重新整理;量之前先讀版本戳記(`window.__build`)比對;`curl` 沒有 service worker,是裁判。
出處:原 5.1

### [someone-elses-server] 量到別人的伺服器
**症狀**:一個莫名其妙的 404;量了好一陣子的數字對不上任何改動。
**為什麼騙人**:背景起的靜態伺服器因 port 被另一個 session 佔用而**靜默退出**,你接著對那個 port 量的是別的專案。多 session 時 port 是共用資源,背景失敗不會立刻看到。
**判準**:量之前先證明那個 origin 是你的——種一個只有你的 build 會回傳的標記(檔案、版本戳記、剛改的常數),先讀它再開始量。
出處:原 5.14

### [synthetic-events] 合成事件不是真的互動
**症狀**:用 `el.click()` / 合成 tap 做的 guard 全綠,真人操作卻壞。
**為什麼騙人**:`el.click()` 送出 `detail: 0`,那是 **Enter 鍵**的簽名不是滑鼠;合成 tap 不產生 hover,對 `:hover` 分支毫無證據力。
**判準**:依賴指標細節(detail、hover、pointerType)的分支,合成事件不算證據——真的互動,或截圖。
出處:原 5.7

### [hidden-pane] 隱藏 / 不合成的 pane
**症狀**:測試「跑很久像當掉」,或一堆莫名其妙的失敗。
**為什麼騙人**:隱藏 pane 裡計時器被節流、有限動畫永遠不結束(`await animation.finished` 永不解析)、`innerWidth` 讀到 0。而解法本身會製造新的假失敗:每 100ms 送 keydown 的「解卡幫浦」把所有「必須等待玩家按鍵」的測試弄紅。
**判準**:先確認 pane 可見、有尺寸;任何「解卡」機制,先列出它會干擾哪些斷言。
出處:原 5.8

### [measure-the-container] 量到容器,而不是量到東西本身
**症狀**:「放得下」的量測永遠回答放得下;兩份仔細的量測差出一整個結論。
**為什麼騙人**:縮放自適應的元素量自己的 rect 永遠合身,要量**容器**。從靜態 HTML 推算高度會漏掉 JS 載入後才掛上的元素——一個語言切換鈕就值 69px。
**判準**:量「裝不裝得下」時量容器,而且在 JS 跑完之後量。
出處:原 5.9

### [rounding-at-threshold] 儀器裡的四捨五入,正好磨掉了門檻要分辨的那一位
**症狀**:「最小間距 12.00,通過」——真值 11.9988,判準 ≥ 12。
**為什麼騙人**:`toFixed(2)` 發生在比較之前,儀器物理上分不出「剛好 12」和「差一點不到」,而 12.00 看起來比 11.9988 更像乾淨的通過。同族:同一公式、不同輸入(`max-content` 容器餵不同長度的字串)就不是同一個量。
**判準**:「≥ 門檻」的檢查,格式化只能在最後印出那一步;問儀器解析度跟門檻差幾個數量級;分母與輸入要跟兩端一起固定,挑不隨輸入變的數字當斷言對象。
出處:原 5.15b

### [pipe-eats-exit-code] pipe 吃掉 exit code
**症狀**:`cmd | grep FAIL; echo $?` 印的是 grep 的狀態。`cp 備份 目標 && grep …; git commit` 在 cp 失敗後照樣把注入的缺陷提交了。`grep -c X a && grep -c X b` 在 a 乾淨(印 0、exit 1)時 b 從沒被檢查。
**為什麼騙人**:`&&` 鏈恰恰在一切正常的時候斷掉,失敗方向是「安靜地少驗了幾個檔案」,你看到的是一個 0 和沒有錯誤。
**判準**:狀態從落檔後取(`cmd > out; echo $?`);「注入 → 觀察 → 還原」的還原不能是鏈上的一步,要寫成下一個動作的**守衛**(「樹上還有 FALSIFY 就不准 commit」);逐項檢查各自跑、各自印——`&&` 不是給逐項檢查用的。
出處:原 5.10

### [shared-browser-tab] 瀏覽器 pane 是所有 agent 共用的——你的分頁會被 peer 導走
**症狀**:讀 harness 結果的 JS 回來了,但分頁列顯示上一秒它還在 `:8536`——那是 BE 子 agent 的伺服器,不是你的。
**為什麼騙人**:同一個 pane、同一個 tab,子 agent 的 navigate 跟你的一樣有效;而讀數不帶 origin,看起來完全像你的那一份。[someone-elses-server] 的分頁版。
**判準**:有 peer 在跑時,`tabs_create` 開專屬分頁、每個呼叫帶 tabId;每次讀結果把 `location.href` 和標記檔內容一起印進同一個 JSON。
出處:elevator_inc #136 驗證(2026-09-07)

## 假綠——guard 本身是死的

### [circular-expectation] 檢查從被檢查的東西身上取得期望值
**症狀**:最常見、最難看見的假綠。從 INSERT 取欄位清單再用同一份讀回來,兩欄對調互相抵銷;期望值由被測資料推導,測的是資料的形狀不是規則。
**為什麼騙人**:規則和期望值同源——規則改錯,期望值一起錯,測試沉默通過。
**判準**:如果我把規則改錯,期望值會不會跟著錯?會的話這條沒用。期望值要另外手寫、獨立敘述那條規則。
出處:原 5.2

### [verify-in-working-range] 在能運作的區間驗證儀器
**症狀**:用「這一欄完全線性」證明量測可靠——但線性的是溢出區間,故障只在「裝得下」的區間(`min-height:100vh` 讓裝得下的頁面都回報 0)。
**為什麼騙人**:在能運作的那一半驗證儀器,對壞掉的那一半什麼也沒說。
**判準**:提出驗證時先說出它取樣了哪個區間、總共有哪些區間;路徑上任何飽和 / 夾限 / 釘死的機制,其邊界就是區間分界。
出處:原 5.3

### [name-promises-more] 名字承諾得比斷言多
**症狀**:測試叫「…**and a legal one still costs a turn**」,合法那半從沒斷言回合。
**為什麼騙人**:稽核覆蓋率的人讀名字、打勾、不會打開內容。
**判準**:要嘛補斷言,要嘛改名字。
出處:原 5.5

### [nonempty-population] 對缺席的主張,要先證明現場非空
**症狀**:「按了牆壁什麼都沒發生」——當下沒有牆可以按,這條永遠通過。
**為什麼騙人**:「必須不包含 / 必須沒有改變」在空母體上恆真。
**判準**:先斷言它讀取的區域非空:`assert(walls().length > 0, "沒有牆可撞,這條 guard 從來沒有試過")`。這說的是「**掃描的母體**」,不是「例外清單」——誤用見 [guard-punishes-completion]。
出處:原 5.6

### [unfalsified-guard] 逃過證偽的 guard,不是隨機抽樣
**症狀**:證偽了好幾條 guard,唯獨沒證偽「`tick()` 不得碰 DOM」——邊界的唯一守門員、我反覆引用給 peer 聽的那條。它從來不可能紅:`takeRecords()` 的回傳值被丟掉,500 次 DOM 異動回報 0。
**為什麼騙人**:你會去證偽哪條,跟哪條需要證偽,是負相關的——地基「顯然」對、太便宜、而且你一直在引用它。引用的感覺跟使用幾乎一樣,但引用不執行任何東西。
**判準**:不要問「我證偽過哪些」,問「**我沒證偽過哪些,為什麼跳過**」;理由是「太基礎」「一直綠」「我常引用它」的,就是下一條要弄紅的。排空型 API(`takeRecords`、`drain`、`poll`)別丟回傳值。
出處:原 5.15

### [red-capable-vs-alive] 「能紅」不等於「這一次是活的」
**症狀**:修好 guard 後兩種證偽:讓產品寫 DOM → 紅;把 observer 指向 detached `<div>` → 綠,0 mutations,跟乾淨通過無法區分。
**為什麼騙人**:「有能力紅」是程式碼的性質,「這次瞄準正確的東西」是那次執行的性質。瞄錯目標、提早 disconnect、選擇器選到空集合——結果都是一個充滿自信的零。
**判準**:存活證明放進 guard 本身:故意製造一次違規要求它看見,或先斷言母體非空([nonempty-population])。另一次跑過的證偽只證明它「曾經」有效。
出處:原 5.16

### [cleanup-as-precondition] `try/finally` 擋不住「呼叫被殺掉」
**症狀**:量測用 `try/finally` 還原注入的欄位;兩次逾時被中止,`finally` 沒跑,下一次的基準線被污染。
**為什麼騙人**:`finally` 保證「這一次正常結束會收尾」,不保證「下一次開始是乾淨的」;逾時、中止、行程被殺、分頁被搶走,每一種都跳過它。
**判準**:清理寫成「**下一次使用前的前置檢查**」(「這張表現在乾淨嗎?」——那句真的紅了兩次),不能只寫成這一次的收尾。它不是防禦性程式碼,是存活對照。
出處:原 5.16b

### [green-path-unseen] 為「綠色也要看得見」而寫的訊息,你看過綠色那一列嗎
**症狀**:harness 裡 48 條為「通過時也印數字」而寫的訊息,一次都沒顯示過——`ok(cond, msg)` 是 `cond ? true : msg`。我還在交付訊息寫過「全綠也會印出最小值」,一句從沒親眼確認的話。
**為什麼騙人**:失敗路徑每次證偽都走一遍,**成功路徑沒有人看**——而追蹤緩慢侵蝕的數字永遠長在成功路徑上。
**判準**:凡是為「通過」寫的輸出(通過訊息、成功後的清理、nothing-to-do 分支),去看一次通過的那一列。
出處:原 5.21

### [guard-punishes-completion] 一條會懲罰「把工作做完」的 guard
**症狀**:五張背債表各配 `nonEmpty(表)`;還完最後一筆債的人會把 harness 弄紅。peer 說得準:「刪了一定會紅,不刪反而不會。」
**為什麼騙人**:[nonempty-population] 的誤用——那條講「掃描的母體」不可空,不是「例外清單」不可空。背債表空掉是**目標狀態**,不是儀器故障;這種 guard 會教下游不要把事情做完。
**判準**:對每條 guard 問「把它守護的東西做到完美,它是什麼顏色?」必須是綠。任何「數量 > 0」的斷言(至少一個 TODO、changelog 非空)先問那個 0 是不是勝利。
出處:原 5.24

### [product-verb] 這個產品的動詞是什麼?哪一條檢查會因為它停擺而紅?
**症狀**:一版刻意過度積極的錯誤修法(「車上有人就誰都不接」)72 pass / 0 fail;送達率比不修還差 7.7 個百分點。七十二條守內容、顏色、翻譯,沒有一條問「電梯有沒有在送人」。
**為什麼騙人**:周邊比核心容易寫(grep vs 跑模擬),guard 長在容易長的地方,數量讓人以為覆蓋率也長了;核心「顯然有人看」——壞 7.7 點看不出來。
**判準**:答不出「哪條檢查會因為動詞停擺而紅」就先寫那條。門檻要鬆(抓崩塌不抓漂移),實測值印在通過訊息裡([green-path-unseen]);被註解掉的 guard 比沒有更糟——它還在假裝有人在看。
出處:原 5.27

### [dead-branch-fix] 一條在今天的資料上永遠不執行的修正,會通過所有測試
**症狀**:issue 指定「跳過永遠裝不下的乘客」寫成 `size > cap`;最小載客量 4、最大 size 也是 4,`4 > 4` 恆假。照字面實作全綠,因為它什麼都沒改。
**為什麼騙人**:[nonempty-population] 的規格版——「修正」的母體是空的,綠的是產品不是儀器。附帶:複驗時 grep 到兩個 `size:6`,都在註解裡——寫進每份 brief 的「別把註解當資料」不會讓你自己免疫。
**判準**:寫下條件後先問「今天有幾筆資料會讓它成立?」答案是 0,你交出去的是永不執行的分支,測試無法告訴你,因為「沒有改變」正是它預期的結果。
出處:原 5.28

### [vacuous-consistency] 「整批一致」在整批都空的時候恆真——比較型斷言要有一端釘在絕對值上
**症狀**:harness 第 22 組比「summon 同伴六個欄位跟本尊一致」。BE peer 證偽自己的探針時發現:拿掉 helper 的 `evId`,本尊和同伴一起 undefined,「一致」照樣綠;而本尊是用 evId 認的,整批漏掉時還回報「儀器壞了」。
**為什麼騙人**:[nonempty-population] 的比較版——母體非空了,但比較的**參考端**是空的。`undefined === undefined`,而且看起來像「大家都一樣」。用被檢查的欄位去認本尊,則是 [circular-expectation] 的小型版。
**判準**:任何「A 跟 B 一致」的斷言,先把 A 對到一個獨立來源(事件列、設計文件)的絕對值;認本尊不可以用被檢查的欄位。peer 證偽儀器抓到的洞 → 回報,orchestrator 修,不改 tests/。
出處:elevator_inc #136(2026-09-07)

## 取樣與數字

### [discriminating-points] 取樣要取「能分辨的點」,不是方便的點
**症狀**:設計文件同時寫一條公式和一張三列表格,前兩列一致、第三列不同;每個讀過的人都抽在一致的兩點上,錯誤公式活過兩版。
**為什麼騙人**:在方便的點取樣會**確認**一個 bug。
**判準**:先問哪些點能分辨兩種解釋,只在那裡取樣;N 處描述同一件事時全部列出來看誰跟誰一致——少數的通常錯,但要數過才知道誰是少數。
出處:原 5.12

### [initial-state-sample] 取樣點裡有沒有「系統的起始狀態」?
**症狀**:掃三種規模挑 12 / 30 / 80,系統起始值是 5;peer 在 5–10 找到違規,修好後在 5 層量到的違規(25.5%)比我取樣的任何一點都嚴重。
**為什麼騙人**:我挑的「小」是我覺得像小的數字。起始狀態是唯一所有人保證都經歷的點,權重最高,卻不在憑直覺列的等距序列裡。
**判準**:取樣清單要有預設值 / 初始值 / 空清單 / 單一元素 / 第一次執行(無快取無存檔)/ 剛好在邊界上的那一個。
出處:原 5.26

### [grid-count-not-absolute] 取樣密度下的計數,不要當成絕對值報出去
**症狀**:「門檻 9 只剩 1,639 個可行點」——那是 step 4 網格的計數,全解析度 111,110,比例兩邊都 0.6%。這句話被我寫進後面每一份 brief;同一個粗網格還讓我說「藍色完全不存在」,實際門檻 9 有 1,864 個藍點。
**為什麼騙人**:兩次量的是同一件事,錯的是引用方式;粗網格漏掉薄的那條帶,而薄的帶正是你想知道在不在的那種。
**判準**:網格數出來的計數,報出去換成比例、或把網格寫在同一句;「完全沒有 X」對取樣密度特別脆弱——要宣告不存在,先加密網格。
出處:原 5.22

### [asymmetric-samples] 兩邊的樣本大小不一樣,而小的那邊剛好是支持行動的那邊
**症狀**:「不要修」12 顆種子 → −1.50pp;「它幫忙」4 顆種子 → +3.9pp。補到 12 顆後 +3.9 變 −0.33,效果消失。
**為什麼騙人**:各自誠實,錯只在比較裡。方向不是巧合:支持你想做的結果容易被當「夠了」而停下,擋住你的會再跑一輪——**嚴謹度沿著偏好分布**。沒有人在看樣本數的對稱性,它不會自己浮出來。
**判準**:比較兩個 arm 前先把樣本數寫在同一行;問「哪一邊拿到比較鬆的儀器?」若剛好是你想要的結論,先補那一邊。SKILL.md 第六節的樣本量版。
出處:原 5.29

### [wrong-criterion] 修一個實例只是推給下一個 → 判準取錯了,不是資料錯了
**症狀**:guard「候選池不可只剩一列」;peer 掃完全部窗,唯一解會讓另一列變成唯一候選——它停下來問,沒順手改第二列。
**為什麼騙人**:「唯一候選」不是缺陷,問題是那列吃掉 20% 預算;改成「佔比 ≤ 15%」後第二列不用改。附帶:peer 回報兩個測量,我只複驗一個就寫「它是對的」——另一個是雜訊,已進了 commit。
**判準**:修法是「再改一個本來就好的地方」→ 懷疑判準不是資料;打地鼠的不變式是把症狀寫成規則,真規則在後一層、常是連續量。背書要逐項([true-sentence-wrong-scope])。
出處:原 5.25

## 主張與規格——句子本身騙人

### [true-sentence-wrong-scope] 一句正確的話,配上錯誤的適用範圍
**症狀**:「這個檢查不再能證明 SQL 字串一致」——真的,但讀者自己補上一個大得多的範圍,去「修復」一個更好的設計。
**為什麼騙人**:測量真、句子真、範圍錯;因為測量真實,結論感覺理所當然,從句子內部看不出來。
**判準**:同一段話裡同時寫「還證明得了什麼」和「不再證明什麼」。適用於 commit message、交接、issue 留言、驗證報告——「我沒驗到 X」不配「我驗到了什麼」一樣誤導。
出處:原 5.4

### [report-is-a-reading] peer 的回報是一次讀數,不是樹的屬性
**症狀**:peer 回報「BELT_SECONDS 從 12 改成 60」,寫的當下是真的;幾小時後我當現況轉述,開 issue 要求做一件早就做完的事,還送給 owner 裁決一個死掉的問題。
**為什麼騙人**:具體而有量測的表格讀起來像系統性質,不像快照;產品裡一段過時註解還在替它背書。往上呈報不會洗白未經查證的前提,只把你的錯誤轉成對方的錯誤決定。
**判準**:轉述任何「現況」之前自己讀那個值,`git log -S` 只花幾秒。標籤要寫出被固定住的變數——被引用出去的是標籤,不是旁邊的散文。
出處:原 5.18

### [naming-is-not-scanning] 把 bug 寫成一個「類」,不等於掃過那個類
**症狀**:找到一條不可能紅的 guard,我複驗、證偽、寫進記憶、寫成本檔一節、推上公開 repo——然後宣布另一份 harness 全綠,而它有一模一樣的那一行。是另一個 peer grep 出來的。
**為什麼騙人**:把它命名成類的動作,感覺起來就是推廣的步驟,所以真正推廣的動作從沒被排進待辦;寫得越完整,越像處理完了。
**判準**:命名成類的那一刻,下一個指令是 grep,在寫心得**之前**跑;先掃自己的檔案。掃之前先講出一個正確用法,才不會把正確的也吃掉。
出處:原 5.17

### [lesson-not-self-applied] 你寫進每一份 brief 的那條教訓,你自己的檔案掃過了嗎
**症狀**:每份 brief 第 13 條寫「用解析後的表,不要 grep 原始碼」;我自己 harness 的第 11 組是 `SIM_SRC.match(/codex\.(\w+)/g)`,把警告註解讀成資料——插一條物理上拿不到的成就,69 pass / 0 fail。調查中途又用 grep 掃事件,掃出空集合。
**為什麼騙人**:寫進 brief 讓它變成規格,而派工的動作讓你覺得已經處理掉——它只是被轉發了。
**判準**:教訓寫進 brief 的那一刻,先對自己的檔案跑一次。[naming-is-not-scanning] 的加強版。
出處:原 5.23

### [size-not-hit-target] 尺寸不是點擊目標:規格寫了容易斷言的那個屬性
**症狀**:「每個點擊目標兩軸 ≥ 32px,要斷言不要用眼睛」——分頁確實 63×52,但抽屜把手蓋住前四個分頁;手機上買不了機器人。靠截圖發現。
**為什麼騙人**:尺寸是元素自己的屬性,可及性是「加上所有在它之後繪製的東西」。尺寸容易斷言,正是它被寫進規格而真正的性質沒有的原因。peer 正確實作了我的條件——綠是誠實的,也沒用。
**判準**:斷言「這個元素是不是它自己中心點上最上層的東西」(`elementsFromPoint`),每個寬度都跑;暫停遮罩會讓全部不可及,先關掉它。規格點名「尺寸」時,先問真正決定結果的屬性是什麼。
出處:原 5.19

### [no-scroll-not-fits] 「沒有捲軸」不等於「裝得下」——被丟掉的溢出量得更好看
**症狀**:`scrollHeight === innerHeight`、零內部捲軸、任何數量都一樣——因為地板把裝不下的直接丟掉:SE 上畫 5 格,玩家有 40 台,其餘不存在。縮到 32×26 後 52/0 全綠,名牌 4px 高、命中區互相壓進 6px。
**為什麼騙人**:「裝得下」和「溢出被丟掉」從每個捲動指標看都相同,而丟掉的版本分數更好看;會數數的 guard 不會判斷。
**判準**:視窗容納類需求斷言「畫了幾個」對「擁有幾個」,由渲染器公布;被丟掉的數量從幾何算、不從 skip 迴圈算;「裝得下且能用」只有截圖分得出。
出處:原 5.20

## 通道與協作

### [dispatch-not-delivered] 派工回報成功,不代表對方收到
**症狀**:九則訊息、兩小時、三次「他們開工了嗎」,全在一條靜默不送達的通道上;`isRunning: false` 從第一分鐘就在那裡。
**為什麼騙人**:agent 佇列送到對方的 agent loop,對方沒在跑就永遠不排空、不出現在 transcript;`success: true` 只代表名字解析到一個可達的 agent。而且自帶假證偽:送給不存在的名字被拒,只證明位址解析([true-sentence-wrong-scope])。
**判準**:先看對方 `isRunning`;派完去對方 transcript 搜自己訊息裡的特徵字串;**確認送達之前不要開始等**。回程用痕跡不用宣告(SKILL.md 第三節)。
出處:原 5.11

### [diagnosis-outlives-validity] 診斷正確,但活得比有效期久
**症狀**:前九則確實沒送到,診斷對;換通道後三次全中——我還繼續回報「它們停擺了,請 owner 去戳」,在手上已有能叫醒它們的機制之後。另一半:把 interactive session 的「做完在等輸入」讀成「掛掉」。
**為什麼騙人**:舊結論沒被推翻,只是沒被重新檢查;「安靜」的兩種原因症狀一樣。
**判準**:修好一個機制後,把所有「因為它壞掉」而下的結論標為待重驗。對方安靜時先分「壞了」還是「做完在等」——後者只要再給一則輸入,而每則訊息只買一個回合,所以每則要裝下一個完整的工作單位。往上報之前,先確認不是你自己能做的事。
出處:原 5.13
